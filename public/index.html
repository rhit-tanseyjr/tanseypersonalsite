RISC-V Embedded Operating System Kernel

Sept 2025 – Present

Developing a bare-metal embedded OS for 32-bit RISC-V from scratch, running under QEMU with a VirtIO block device. Everything from bootloader to userspace shell is hand-written in C and assembly without external libraries. Implements full privilege separation (S-mode/U-mode), Sv32 two-level page tables, a round-robin scheduler, a VirtIO block driver, and a tar-based file system. Currently extending the kernel with interrupt controllers, preemptive multitasking, and a broader device driver framework.

Overview & Kernel

• Bootloader sets stack pointer via linker-defined __stack_top and jumps to kernel_main in a naked assembly boot stub • BSS zero-initialized at startup via memset over [__bss, __bss_end) before any C runs • SBI integration: console I/O via ecall into OpenSBI using legacy putchar/getchar extensions • Trap handling via kernel_entry: full 31-register context save/restore using csrrw sp, sscratch, sp for stack switching • Syscall dispatch: scause == 8 routes to handle_syscall, advancing sepc += 4 to skip the ecall on return • PANIC macro captures __FILE__ and __LINE__ and halts — used as a hard assertion throughout the kernel

Process Scheduler

• Cooperative round-robin: yield() scans procs[] for the next PROC_RUNNABLE process with pid > 0 • Idle process (pid=0) created at boot as fallback; kernel panics if execution ever returns to it • Context switch: naked assembly saves 13 callee-saved registers (ra, s0–s11), swaps sp via sw sp,(a0) / lw sp,(a1), restores next process's registers • Per-process 8 KiB kernel stacks embedded in struct process; initial stack frame pre-loaded with user_entry as return address • satp CSR written on every context switch with SATP_SV32 | (page_table / PAGE_SIZE), bracketed by sfence.vma TLB flushes • sscratch updated to each process's kernel stack top so trap entry always finds the correct stack • Process exit: SYS_EXIT marks state PROC_EXITED and calls yield(); slots reused via PROC_UNUSED check

Virtual Memory & Paging

• Sv32 two-level page table: 10-bit VPN[1] indexes root table, 10-bit VPN[0] indexes leaf PTE — matches RISC-V Sv32 spec exactly • map_page() allocates a second-level table on demand if root PTE lacks PAGE_V, writes leaf as (paddr/PAGE_SIZE)<<10 | flags | PAGE_V • Kernel identity-mapped into every process over [__kernel_base, __free_ram_end) with PAGE_R|W|X — allows trap handling without a page table switch • VirtIO MMIO region (0x10001000) explicitly mapped PAGE_R|W in each process so device registers are accessible from kernel code in any address space • User binary copied page-by-page from embedded shell.bin.o into physical pages, mapped at USER_BASE = 0x1000000 with PAGE_U|R|W|X • Partial last page handled: copy size clamped to min(PAGE_SIZE, remaining) to avoid over-reading the image • user_entry naked stub sets sepc = USER_BASE, sstatus.SPIE = 1, executes sret to drop into U-mode

Disk I/O & File System

• VirtIO 1.0 legacy MMIO block driver targeting virtio-blk-device on QEMU bus at 0x10001000 • Init sequence: reset → ACK → DRIVER → set page size → init virtqueue → DRIVER_OK; panics on magic/version/device-ID mismatch • Virtqueue allocated as one physically contiguous page via alloc_pages, written to VIRTIO_REG_QUEUE_PFN as a page frame number; queue size fixed at 16 • virtq_kick() posts descriptor to available ring, increments index, issues __sync_synchronize() barrier, notifies device via VIRTIO_REG_QUEUE_NOTIFY • virtq_is_busy() polls used ring index against last_used_index for completion without interrupts • Disk capacity read as 64-bit sector count from VIRTIO_REG_DEVICE_CONFIG; bounds-checked before issuing any request • Tar-based file system layered on top of the block driver for reading embedded files at boot • MMIO accessors use volatile pointer casts; all structs marked __attribute__((packed))
